# 首次运行交互话术 + 常规 FAQ

本文件供 agent 在**阶段零（环境检测）**直接使用，给出与用户沟通的标准话术，并汇总用户最常问的问题。
目标：让首次使用 geo-cms 的人**一分钟理解「这是个桥、不是写手」**，并清晰知道要补什么外部能力。

本技能不生成内容、不设定 GEO 规则 —— 这话必须在开场就讲清楚，避免后续误会。

---

## 一、首次运行交互话术（阶段零脚本）

> 适用时机：检测到仓库内没有 `.geo-cms/config.json`（或用户说「第一次用」）。
> 节奏：先讲定位 → 再检测环境 → 逐项确认缺失能力 → 用户拍板后进入 Setup。

### 第 1 步：开场定位（必须说，不长篇）

> 「geo-cms 是个**桥接**技能，不是写手：它把你的知识库文章搬进官网源码、把官网送上部署平台、把结果回库；
> 但**文章正文我来搬不我来写**，**GEO/SEO 规则由外部 GEO 技能或在线检索说了算**，我最多帮你缓存这些规则。
> 所以第一次需要先确认环境里有哪些外部能力，缺的我们一起补齐。」

### 第 2 步：环境自检（agent 内部执行，不打断用户）

调用 `Skill` 工具枚举已装技能 + 读取连接器连接状态，对照「外部依赖契约」四能力打标：

| 能力 | 检测到的来源 | 状态 |
|------|-------------|------|
| `kb-export`（知识库导出） | tencent-docs / feishu / ima / 无 | available / missing |
| `geo-optimize`（GEO 优化） | geo-zh 等 GEO 技能 / 无 | available / missing |
| `deploy`（部署上线） | edgeone-pages 连接器 / 自有服务器 / 无 | available / missing |
| `browser-verify`（验收） | agent-browser / playwright / 无 | available / missing |

### 第 3 步：展示自检结果 + 协商补齐（核心对话）

模板（按缺失项裁剪）：

> 「我查了一下当前环境，四项外部能力的情况：
> - 知识库导出：✅ 已连 `腾讯文档`（或飞书 / IMA）
> - GEO 优化：❌ 没装 GEO 技能 → 我可以 `find-skills` 帮你找并装一个（如 geo-zh），或者本轮先走 WebSearch 降级（规则未经专业 GEO 技能把关，会明确标注）
> - 部署上线：✅ 已连 `EdgeOne Pages`
> - 浏览器验收：❌ 没装浏览器自动化 → 我可以 `find-skills` 装 `agent-browser`，否则用内置最小脚本降级核对
>
> 你看怎么处理？一般建议：GEO 优化装一个专业技能，验收装一个浏览器技能；部署必须有来源（平台或自有服务器）。」

**分支处理：**
- 用户同意安装 → 调 `Skill` `command="find-skills"` 查找，或引导连接连接器；装好后回写 `config.capabilities`。
- 用户选「WebSearch 降级」→ 仅 `geo-optimize` 允许，需在 `config.capabilities` 标注 `mode: "degrade-websearch"` 并口头告知风险。
- `deploy` 无任何来源且用户不提供 → **停止**，明确告知「没有部署能力本技能无法上线，请先准备托管平台或自有服务器」。

### 第 4 步：固化映射并确认

> 「我把依赖映射写进了 `config.capabilities`：
> kb-export=腾讯文档，geo-optimize=geo-zh，deploy=EdgeOne Pages，browser-verify=agent-browser。
> 确认无误我们就进入初始化（填 git 库、勾选知识库、填部署信息）。」

用户确认后 → 进入 SKILL.md「阶段一」。

## 二、常规 FAQ（用户最常问）

### Q1：geo-cms 能帮我写文章 / 生成官网内容吗？
**不能。** 它是桥接技能，只搬运、合并、落库你**提供**的内容或知识库导出的内容，不创作正文。
需要写稿请另用内容生成类技能，或直接在知识库写好再同步过来。

### Q2：GEO 优化怎么做？规则谁定的？
规则**不是 geo-cms 定的**。优化由环境里的 GEO 技能（如 geo-zh）或在线检索（WebSearch）提供权威口径；
geo-cms 只负责把优化应用到源码、并把外部产出**缓存**到 `.geo-cms/specs/` 以便下次复用。
所以「这次为什么这么改」的答案在外部 GEO 能力，不在本技能。

### Q3：为什么我必须连部署平台 / 提供服务器？
部署是**必要外部能力**，不可降级。geo-cms 不实现部署 API，只能编排调用 EdgeOne Pages 等连接器，
或你对自有服务器做 rsync。没有任何部署来源时，本技能会停止，不会「假装上线」。

### Q4：知识库一定要连腾讯文档 / 飞书 / IMA 吗？
不强制。最稳的是 `markdown` 类型：你直接把 `.md` 文件丢进 `.geo-cms/inbox/<kbId>/` 即可，
无需任何连接器。连连接器只是省去手动拷贝这一步。

### Q5：为什么每次部署前都要做 GEO 优化？
因为你的需求明确要求「每次优化一致且有时效」。机制是：本地已有规范缓存则并行「用缓存优化 + 实时刷新」，
优化后再把增量新规范并入缓存。这样既不每次重头搜，又不丢最新口径。规则权威仍在外部 GEO 能力。

### Q6：规范缓存（specs/）会越改越乱吗？
不会。bridge 只**补充不打翻**：`--append` 只加本地没有的新规范条目（按 TAG 去重），不覆盖既有口径，
且每条都标注来源 URL。要清理或调整规则，由你或外部 GEO 技能决定，不在本技能内自动改写。

### Q7：支持我的网站吗？（形态边界）
仅支持 **SSG 纯静态产物**：Next.js `output:export`、Astro `static`、Hugo、VitePress、Jekyll、11ty 等。
遇到 SSR 无静态导出、依赖数据库的动态 CMS、无预渲染纯 SPA —— 会停止并说明，不做带服务端依赖的上线。

### Q8：为什么先要验证 git 写权限？
因为最后一步要把更新**提交回代码库**（commit + push）。如果只有读权限，合并优化好了却回不去，
等于白做。所以阶段一就循环探测读写，不通不往下走，避免半路卡死。

### Q9：验收一定要浏览器自动化吗？
首选用 `agent-browser` 等浏览器技能真实打开线上页面核对；若没装，降级用内置 `verify_deploy.py`
做最小本地核对（状态码 / JSON-LD / 正文非空 / robots·llms 可达）。降级核对弱于真实浏览器，会标注。

### Q10：首次跑完后会留下什么文件？
仓库里新增 `.geo-cms/`（config.json + specs/ + prompts/ + build-log.md 应提交；inbox/ 建议忽略）、
`content/`（合并后的文章），以及把 `.gitignore` 合并进仓库。本地记忆与字节码不会进仓库（已在 `.gitignore` 排除）。

### Q11：你们会改我的网站模板吗？
**不会主动改，更不会删。** 模板是你选定的（记录在 `config.site.template`），geo-cms 承诺：
非你强制要求，不删页面/组件、不改布局与设计，只按模板既有结构填充内容、新增文章页。
你明确要求改设计时，会引导前端设计技能（社区推荐 frontend-design-v2）执行，
并在构建日志记录「模板变更」，随时可 git revert 回滚。

### Q12：构建日志和提示词是干什么的？
- **构建日志**（`.geo-cms/build-log.md`）：每次同步/构建/上线后自动追加一条
  （同步了几篇、门禁结果、部署 URL、验收结果、模板是否未动、遗留事项），
  是下次更新「接着上次进度」的依据。
- **提示词**（`.geo-cms/prompts/`）：你的两份生产资料 —— `build-prompt.md`（站点怎么建：
  风格/受众/页面/禁改项）、`article-prompt.md`（文章怎么写：选题/结构/口吻/关键词）。
  由你口述、我代存，之后生成文章时转交内容生成技能执行。geo-cms 只收集转交，不代写正文。
